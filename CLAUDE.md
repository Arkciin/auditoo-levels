# CLAUDE.md

Guide for AI coding agents working on this repository. [DESIGN.md](DESIGN.md) explains why the
system is built this way; this file says how to change it without breaking it.

## What this is

Relevé: an offline-first PWA in which French property diagnosticians record the levels and rooms
of a dwelling (*logement*) on site. A React 19 PWA and a Hono + PostgreSQL server share their
domain code and sync through a Replicache-style push/pull engine. Non-negotiable: it works offline
for hours, never loses data, and is fast with one thumb.

## Rules that keep the sync correct

1. **Every data change is a mutation.** UI code calls `useSafeMutate()` (or `client.mutate`). Never
   write IndexedDB, call the API or patch state directly.
2. **Mutators are deterministic** and run on device and server alike. They may use only `tx`,
   `args` and `ctx.timestamp`: no `Date.now()`, `Math.random()`, `newId()`, I/O or logging. Ids and
   positions are generated by the caller and passed as arguments.
3. **"Cannot apply" is `throw new MutationRejectedError(…)`.** The server treats any other
   exception as transient: the push fails, the device retries forever and its queue is blocked. A
   rejected mutation is acknowledged, listed in the push response, and reported to its user.
4. **Edit wins over delete.** A mutator that edits an entity sets `deletedAt: null` and revives its
   parents (`reviveLevel`, `reviveProperty`). Deletes are soft and idempotent, and each `delete*`
   has a `restore*`.
5. **Puts replace the whole entity.** Spread the current row (`{ ...space, name }`);
   `ServerTx.put*` writes every column. So a create first refuses an id that exists, deleted or
   not (`requireNewSpace`…): written over, a room could change logement.
6. **Positions** come only from `positionAtIndex(siblings, index)`, `positionAtEnd(siblings)` or
   `positionBetween`, with `siblings` sorted by `compareByPosition` and without the moved item.
   Compare with `comparePositions` or `compareByPosition`, never `localeCompare`. A new position
   column needs `COLLATE "C"`.
7. **Strict input, loose rows.** Input schemas may tighten (`nameSchema`); schemas of rows read back
   must stay loose, or one legacy row makes every pull fail and blocks the device.
8. **Migrations are append-only** (`apps/server/src/db/migrations.ts`): never edit a shipped one.
   IndexedDB changes go through `DATABASE_VERSION` and `upgrade()` in `storage.ts`. Never delete or
   recreate the `outbox` store: its key generator allocates mutation ids.
9. **The service worker never caches `/api`.** Data belongs to IndexedDB and the sync engine.
10. **Every push must fit the server's body limit** (`MAX_REQUEST_BYTES`,
    `packages/shared/src/protocol.ts`): a push refused for its size is retried as it is, forever.
    Devices cut pushes at `MAX_PUSH_BYTES` (`takePushBatch`) and `mutate()` refuses a mutation
    that would not fit one on its own. Still bound every list in a mutation's arguments
    (`MAX_DUPLICATED_SPACES`), so that every valid mutation can be queued, and keep the "largest
    push" test of `app.test.ts` building the largest one.
11. **No outbox entry may lock a device out.** Another version of the app may have written it.
    Read the outbox through `readStoredMutation`, replay it with `applyMutations` (any failure
    there means "does not apply here": reported once, kept for the server to judge), and check
    `isReadable` before reading a queued mutation's fields (descriptions, the sync sheet). Loading,
    replaying and describing the queue never throw.

## Conventions

- **TypeScript strict** everywhere (`noUncheckedIndexedAccess`, `verbatimModuleSyntax`, no unused
  locals or parameters). No `any`; a cast only at a typing boundary, with a comment saying why.
  The web app targets ES2022 (older Safari on tablets), and so does its typecheck of the shared
  code it imports: no `toSorted`, `findLast` or other ES2023 methods outside the server.
- **Biome** formats and lints: 2 spaces, double quotes, 100 columns, sorted imports. Run
  `pnpm format`; CI runs `biome ci`.
- **Comments explain why** (a constraint, a trap, a tradeoff), not what the next line does. Keep
  existing comments true when you change the code under them.
- **French UI, English code.** UI copy is French (the users are French diagnosticians); code,
  comments, commits and docs are English. Use `quote()` (`apps/web/src/sync/describe.ts`, the only
  one) for « … » with non-breaking spaces and `plural()` for counts ("3 pièces").
- **Touch first.** `Button` sizes give 44 px targets; inputs keep `text-base` (16 px, or iOS zooms
  in); interactive elements inside a swipeable row get `data-no-swipe`; every control has an
  accessible French name, which the e2e and component tests select by, and which starts with its
  visible text when it has some (WCAG 2.5.3: speech input users say what they see). A gesture that
  deletes a lot (a level, a logement) only reveals a button (`SwipeToDelete`'s `confirmLabel`).
- **The focus never falls to the page body**, where keyboard and screen reader users lose their
  place, and where a phone opens no keyboard: after a delete it goes to the next row, after a
  rename back to the name. A menu item that opens a field or a sheet acts in the menu's
  `onCloseAutoFocus` (see `SpaceRow`), and a row drops its menu while its name is edited: a menu
  still closing takes the focus back.
- **Reading data**: components use `useView(selector)` with selectors memoized per snapshot
  (`apps/web/src/sync/selectors.ts`), and `useSyncStatus()` for the status alone. Event handlers
  that compute a position or a name read `client.getState().view`: taps can outrun React renders.
- **Design tokens** live in `apps/web/src/styles.css`: use token classes (`bg-primary`,
  `text-muted-foreground`, `border-rule`…), no raw colours, no shadow other than `shadow-drag`.
- `components/ui/` is shadcn/ui code we own: edit it freely, keep its touch sizing.
- `apps/web/src/routeTree.gen.ts` is generated by the router plugin and committed: never edit it.

## Tests are part of the change

- Shared logic: `packages/shared/src/*.test.ts`. Server: `apps/server/src/**/*.test.ts`, on
  in-memory PGlite (`createTestDb()` in `apps/server/src/testing.ts`). Sync engine:
  `apps/web/src/sync/*.test.ts`, on fake-indexeddb against `MemoryServer`.
- Components and screens: `*.test.tsx` next to them in `apps/web/src/components` or
  `apps/web/src/features`, which run in happy-dom (project `web (dom)`). Drive them with Testing
  Library and user-event by role and French accessible name, assert on what the user sees; a
  component that reads data gets a real `SyncClient` (`TestDevice`). happy-dom has no layout:
  stub sizes (`offsetWidth`) when behaviour depends on them.
- E2E specs import `test` and `expect` from `./support`, whose fixtures are two gates: any
  Content Security Policy violation fails a test (no inline script, no `eval`, no `style`
  attribute in markup; React's `style` prop is fine), and so does an uncaught exception.
  `accessibility.spec.ts` fails on a serious or critical axe violation: a new screen or sheet gets
  an `expectAccessible` step there, a new menu an `expectAccessibleMenu` one.
- In e2e tests, gesture like a finger (`tap()`, the swipe and drag helpers of `support.ts`), and
  check `toBeFocused()` before typing into a field a tap opened: `locator.press()` and `fill()`
  focus the element themselves, and once hid a field that never got the focus.
- Colours: a new pairing of design tokens gets a line in `apps/web/src/styles.test.ts`, which
  checks WCAG AA contrast in both themes.
- The convergence simulation (`apps/web/src/sync/convergence.test.ts`) must stay green, and must
  know every mutation (`simulateUser`): it fails when a mutation kind is never exercised.
- `MemoryServer` mirrors the server's protocol rules: change a rule in both, test it in both.
- UI changes: run `pnpm build && pnpm e2e`; update `apps/web/e2e/support.ts` when labels change.
  SQL changes: also `pnpm e2e:postgres` where PostgreSQL is installed (CI runs it on PostgreSQL 18).

## Checklist: a new field, end to end

Example: a room's surface area, in m², optional.

1. **Intent.** Add a mutation, `setSpaceArea { id, area }`, rather than widening `renameSpace`. The
   server re-runs mutators on its current row, so separate intents never clobber each other.
2. **Schema** (`packages/shared/src/schemas.ts`): an input schema for the value (positive, bounded),
   and `area: z.number().nullable().optional()` on `spaceSchema`. Optional, because rows already in
   a device's IndexedDB lack it, and a pull only resends rows that change.
3. **Mutator** (`packages/shared/src/mutators.ts`): the arguments schema in `mutationArgsSchemas`,
   then the mutator: `requireSpace`, `reviveLevel(tx, space.levelId)`, then
   `putSpace({ ...space, area, deletedAt: null })`. Also set `area: null` in `createSpace`, and in
   the rooms `duplicateLevel` creates (or carry the source's areas in its arguments): optimistic
   rows must equal server rows.
4. **Protocol**: nothing to add. `mutationSchema` (`packages/shared/src/protocol.ts`) derives one
   envelope per entry of `mutationArgsSchemas`, so the server can never reject the new mutation as
   invalid for lack of one.
5. **Migration** (`apps/server/src/db/migrations.ts`): append `004_space_area` with
   `ALTER TABLE spaces ADD COLUMN area double precision CHECK (area > 0)`. Not `numeric`: both
   drivers return it as a string, which fails the pull schema.
6. **Server mapping**: `area` in `SELECT_SPACES` (`apps/server/src/sync/queries.ts`) and in the
   insert and upsert of `ServerTx.putSpace` (`apps/server/src/sync/server-tx.ts`).
7. **Device**: describe the mutation in French in `apps/web/src/sync/describe.ts`: what it does
   (`describe`), what was not done if it is rejected (`notDone`), and the entities its mutator
   requires (`missingEntity`). Exhaustive switches: TypeScript insists. Read the field as
   `space.area ?? null`.
8. **UI** (`SpaceRow` in `apps/web/src/features/structure/structure-board.tsx`): a compact field
   with `inputMode="decimal"`, the French decimal comma, 16 px text, a 44 px target and
   `data-no-swipe`, saved with `useSafeMutate()("setSpaceArea", …)`.
9. **Tests**: the mutator, edit-wins included (`packages/shared/src/mutators.test.ts`); a push and
   pull round trip (`apps/server/src/sync/sync.test.ts`); the descriptions, rejection included
   (`describe.test.ts`); a weighted kind in the convergence simulation; a component test and an
   e2e step if users see it.
10. **Verify**: `pnpm check`, then `pnpm build && pnpm e2e` (and `pnpm e2e:postgres`).
